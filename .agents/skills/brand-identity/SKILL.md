# Adaptive Brand Identity & Multi-Archetype Architecture Standard

## Resumen Ejecutivo

Esta habilidad establece el marco tri-adaptativo y multi-arquetipo para gobernar la **identidad de marca personal del desarrollador**, la línea base institucional y los estándares de diseño y stack técnico en proyectos gestionados con Google Antigravity.

Opera en **Modo Multi-Arquetipo Adaptativo**:
1. **Marca Personal del Desarrollador**: Establece la autoría, filosofía de ingeniería, rigor de tipado y sellos técnicos de **Rogerr Carvajal** (`@rogerrcarvajal`), especialista en soluciones con **Modelos de IA, Agentes Autónomos y Arquitectura Cloud-Native**.
2. **Arquetipo A (Línea Base Institucional / Académica)**: Estándar para **CEIA / SWGA** (Centro Educativo de Inteligencia Artificial / Sistema Web de Gestión Académica): PHP 8.2+ POO/MVC, PostgreSQL 14+, PDO seguro y HTML5/CSS3.
3. **Arquetipo B (Línea Base Cloud-Native & AI-First)**: Estándar para **Wellness Platform 2.0 (Nutrition Agent) y Nuevos Desarrollos de Vanguardia**: Python 3.11+, FastAPI asíncrono, Pydantic v2, PostgreSQL + pgvector, orquestación de agentes inteligentes, UI Glassmorphic/Tailwind y despliegue a la nube (GCP, AWS) desde GitHub.
4. **Modo Adaptativo Global**: Capaz de analizar, extraer y adaptar tokens visuales y directrices de arquitectura para **cualquier nuevo proyecto empresarial, educativo o startup**.

## Cuándo usar este skill (Triggers)

Invoca este skill cuando:
- Se inicie o configure un nuevo proyecto para registrar la autoría y marca personal de Rogerr Carvajal.
- Se requiera incorporar la cabecera estándar de autoría y badges de ingeniería de agentes.
- Se diseñen o implementen vistas frontend, tarjetas glassmórficas, paletas dark mode o componentes UI.
- Se construyan modelos, servicios, controladores backend o APIs políglotas (Python FastAPI asíncrono / PHP 8.2+ PDO).
- Se definan microservicios de agentes inteligentes, flujos RAG o contenedores Docker para despliegue en la nube (GCP/AWS).
- Se redacte documentación técnica, fichas de producto, especificaciones o notas de release.
- Se audite código existente para validar cumplimiento de estándares de diseño, seguridad y Clean Code.

## 🧭 Flujo de Trabajo Recomendado (Plan → Validar → Ejecutar → Revisar)

1. **Fase 1: Planificación (Identificación de Ámbito y Arquetipo)**:
   - Determinar si el proyecto corresponde al **Arquetipo A** (Core Web / CEIA_SWGA) o al **Arquetipo B** (Cloud-Native & AI-First / Wellness 2.0).
   - Cargar los tokens correspondientes desde `resources/tech-stack.md` y `resources/design.md`.
2. **Fase 2: Validación de Entorno**:
   - Verificar existencia de variables de entorno (`.env`), dependencias sin versiones deprecadas y ausencia total de secretos en código.
3. **Fase 3: Ejecución de Estándares**:
   - Insertar bloques de autoría de Rogerr Carvajal en cabeceras clave.
   - Aplicar variables CSS de diseño (glassmorphism, bordes translúcidos, tipografía Inter/Outfit).
   - Implementar backend con tipado estricto (Pydantic v2 en Python / `declare(strict_types=1);` en PHP) y consultas seguras.
   - Si es Arquetipo B, verificar healthcheck `/health`, Dockerfile multi-stage y workflow CI/CD para nube.
4. **Fase 4: Revisión y Mini Checklist**:
   - [ ] ¿Se acreditó la autoría técnica de Rogerr Carvajal / Antigravity?
   - [ ] ¿Se seleccionó el arquetipo correcto sin forzar restricciones ajenas al proyecto?
   - [ ] ¿Se evitaron colores planos genéricos y se usó modo oscuro curado / glassmorphism?
   - [ ] ¿Toda consulta a base de datos usa parámetros vinculados (PDO / ORM seguro)?
   - [ ] ¿El texto técnico está en español riguroso y sin código comentado muerto?

## ⚠️ Manejo de Errores y Correcciones

- Si una vista o componente generado luce genérico, plano o con colores básicos por defecto, detener la entrega, recargar `resources/design.md` y reconstruir con modo oscuro y tarjetas `.card-glass`.
- Si se detecta código SQL con concatenación directa, refactorizar de inmediato hacia consultas preparadas PDO con parámetros enlazados.
- Ante proyectos con agentes o IA, asegurar que no se bloquee el event loop: usar siempre `async def` y clientes asíncronos (`httpx`, `asyncpg`).
- Ante ambigüedad en los requerimientos visuales o de negocio, consultar al usuario antes de asumir supuestos.

## 🚩 Prácticas Prohibidas vs. Estándar Correcto

| Práctica Prohibida | Estándar Obligatorio Rogerr Carvajal |
|---|---|
| Colores primarios planos (rojo/azul plano) | Modo oscuro quantum, glassmorphism y acentos neón cyan/índigo |
| Código huérfano sin firma de autoría | Cabecera formal de Rogerr Carvajal y estándares de ingeniería |
| Inyección de strings en sentencias SQL | Prepared Statements con PDO / Drivers seguros y tipado estricto |
| Hardcodear URLs de nube o puertos fijos en contenedores | Uso de variable `${PORT:-8080}` y configuración por entorno (12-Factor) |
| Código comentado o archivos temporales muertos | Clean Code; repositorio limpio y profesional |
| Documentación informal o desestructurada | Fichas técnicas estructuradas estilo Google AI Coding con Mermaid |
